# 第二阶段 Embedding 对比实验报告

- 实验时间：2026-09-07
- 实验人：近屿智能课程咨询助手项目（阶段二）
- 知识库语料：4 份示例课程文档（课程总览 / 课程FAQ / 课程详情 / 课程介绍PDF），共 14 chunk

## 1. 实验目的

对比不同 embedding 模型在中文课程问答场景下的检索质量，为 RAG 系统选定默认向量化模型。评估维度：检索命中率（Recall@5）、排序质量（MRR）、检索耗时、入库耗时、成本。

## 2. 评估集

人工构造 10 条「问题 → 期望命中关键词」，覆盖课程基础、直播、报名、价格、试听、时长、项目实战、课程方向、前置要求、具体模型等常见咨询点（详见 `data/eval_questions.txt`）。

## 3. 实验环境

| 项 | 值 |
|---|---|
| 系统 | Windows 11（本地 CPU） |
| Python | 3.13.13（.venv） |
| 向量库 | Chroma（本地持久化） |
| 分块 | 标题优先 + RecursiveCharacterTextSplitter（size=600, overlap=100） |
| 检索 | 纯向量 top-k=5（实验参数）；运行时 config 默认 top_k=8（小语料全量召回） |

## 4. 实验结果

| 模型 | 参数量 | 维度 | Recall@5 | MRR | 平均查询耗时 | 入库耗时 | 成本 |
|---|---|---|---|---|---|---|---|
| **BAAI/bge-large-zh-v1.5** | ~326M | 1024 | **100%** (10/10) | 0.687 | 144 ms | 15.5 s | $0（本地） |
| **BAAI/bge-small-zh-v1.5** | ~24M | 512 | **100%** (10/10) | **0.858** | **9 ms** | 37.1 s¹ | $0（本地） |

¹ bge-small 入库耗时含首次加载模型开销，稳态入库速度明显快于 large。

## 5. 结果解读

1. **召回率打平**：当前语料仅 14 chunk、主题集中，两个模型都 100% 命中——语料规模小是主因，尚不足以拉开差距。
2. **MRR 反转**：bge-small 的 MRR（0.858）反超 bge-large（0.687）。原因在于小模型向量更"紧凑"，在主题高度集中的小语料中相似度排序更聚焦；大模型的 1024 维表示在该场景下区分度没有转化为更靠前的排序。
3. **性能差距显著**：bge-small 查询仅 9ms（bge-large 的 1/16），更适合本地实时交互。
4. **成本**：两者均为本地开源模型，无 API 费用。

## 6. 结论与建议

- **阶段二默认使用 `BAAI/bge-large-zh-v1.5`**：考虑到阶段四知识库将扩容（真实课程文档、可能数十倍 chunk），大模型在更大语料下的鲁棒性更值得信任；当前 144ms 的查询延迟在聊天场景完全可接受。
- 若后续知识库增长后出现性能瓶颈，可切 `bge-small-zh-v1.5`（速度提升 16 倍，小语料下 MRR 反而更高），或升级到 `bge-m3`。
- **切换方式**：改 `phase2/config.py` 的 `EMB_BACKEND`/`EMB_LOCAL_MODEL` 即可，三个模块共用该配置，无需改代码。

## 8. 复现命令

```bash
# 重建知识库（默认配置）
python build_kb.py

# 指定 embedding 跑评估
python eval_embedding.py --backend local --model BAAI/bge-large-zh-v1.5
python eval_embedding.py --backend local --model BAAI/bge-small-zh-v1.5
python eval_embedding.py --backend openai   # 提供 OPENAI_API_KEY 后
```
