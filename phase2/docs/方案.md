# 第二阶段项目方案与实施记录

近屿智能课程咨询助手 · 阶段二：RAG 问答系统 / 意图识别 / 文件处理

- 实施时间：2026-09-07
- 实施方式：本地 Windows + `.venv`（Python 3.13.13），零 API 费用
- 模块独立性：三个模块独立成包，共用 `config.py`，阶段四在 `app.py` 接线集成

## 1. 总体架构

```
用户输入/上传（Gradio，阶段一）
        │
        ▼
① 意图识别（模块2）── 课程问答 / 文件操作 / 闲聊 / 专业咨询
        │                    └─ 低置信度/非法 → Fallback（网络搜索 mock）
        ▼
② 处理通道
   ├─ RAG 问答（模块1）：知识库(清洗→分块→向量化) → 检索 → LangChain 生成
   ├─ 文件处理（2.3）：上传校验 → PDF/docx 解析 → 智能分块 → 入库
   └─ 其他：闲聊直答 / 专业咨询走 RAG
        ▼
③ 存储三件套：对象存储(MinIO/本地) + 向量库(Chroma) + 关系库(SQLite)
        ▲
④ 外部服务：LLM（DeepSeek 云端，key 从 .env 读取）+ Embedding（本地 bge，可切 OpenAI）
```

## 2. 技术选型（含决策理由）

| 组件 | 选型 | 理由 |
|---|---|---|
| LLM | DeepSeek 云端（deepseek-chat，key 从 .env 读取） | 质量高、成本可忽略 |
| Embedding | BAAI/bge-large-zh-v1.5（默认） | 中文优化、本地免费、1024 维；实验报告见 docs/实验报告.md |
| 向量库 | Chroma（本地持久化） | 轻量零运维，小语料足够 |
| 关系库 | SQLite | 零配置；表：documents / chunks |
| 对象存储 | 本地目录（接口抽象，预留 MinIO/S3） | 无 Docker 依赖，接口 S3 兼容语义 |
| 搜索 fallback | mock（接口预留） | 阶段二打通链路，阶段四接真实 API |
| PDF 解析 | PyMuPDF | 中文支持好、速度快 |
| 分块 | 标题优先 + RecursiveCharacterTextSplitter(600/100) | 中文章节语义保留 |

## 3. 模块设计

### 3.1 RAG 问答（模块1，代码在项目根目录）
- `preprocess.py`：raw→corpus 清洗（页眉页脚/编码/空行/去重）
- `chunking.py`：两级分块（章节标题 → 句边界）
- `embedding.py`：统一 EmbeddingClient（openai/local 双后端 + 降级）
- `vectorstore.py`：Chroma 封装（入库/检索/删除/计数）
- `retriever.py`：向量检索 + BM25 混合（RRF，默认关闭；小语料 top_k=8 全量召回，语料扩容后调回 5）
- `qa.py`：LangChain 检索问答链，回答附真实来源

### 3.2 意图识别（模块2，代码在项目根目录）
- `categories.py`：4 类意图定义（含描述/示例），供提示词与校验复用
- `router.py`：LLM 分类 → JSON 解析 → 置信度/合法性校验 → fallback
- `search.py`：搜索接口（mock 实现，接口预留）
- fallback 触发：置信度 < 0.6 / 类别非法 / JSON 解析失败 / LLM 异常

### 3.3 文件处理（2.3，代码在项目根目录）
- `parser.py`：校验（类型/32M/魔数）→ 提取（pdf/docx/txt/html/pptx/ipynb）→ 分块 → 入库
- `storage.py`：对象存储（Local/MinIO）+ SQLite 元数据（documents/chunks）
- 处理状态机：uploaded → parsing → vectorized / failed

- 时间：2026-09-12；范围：模块4 博查 Web Search API 接入（模块3 维持 4 类意图不变）
- 改动文件：
  - `.env`：新增 `BOCHA_API_KEY`（已被 .gitignore 排除，不入库）
  - `config.py`：新增 `SEARCH_BACKEND`（默认 `auto`）、`BOCHA_API_KEY` / `BOCHA_SEARCH_URL` / `BOCHA_SEARCH_TIMEOUT` / `BOCHA_SEARCH_COUNT`
  - `search.py`：新增 `BochaSearchEngine`（POST /v1/web-search，解析 `data.webPages.value[]`）；`SearchEngine` 工厂按配置切换 auto/bocha/mock；网络异常/401/403/429/500 均降级为带原因的兜底话术
  - `router.py`：零改动——`search(query) -> SearchResult` 接口不变，fallback 自动升级为真实搜索
- 验证结果：
  - 博查接口实测 HTTP 200，返回真实网页标题/摘要/链接（source=bocha）
  - `SEARCH_BACKEND=mock` 切换正常（source=mock，不依赖网络）
  - 意图 fallback：低置信度输入返回真实搜索 snippets（2026 人工智能行业动态实测）
  - 意图 4 类全对：course_qa 0.98 / chitchat 1.00 / file_ops 0.98 / pro_consult 0.95
- 运行说明：默认 `auto` 自动切换（有网真实搜索，无网自动降级兜底话术，网络恢复自动切回）；`SEARCH_BACKEND=bocha` 强制真实，`mock` 强制兜底

### 8.1 自动切换升级（2026-09-12）

- `SEARCH_BACKEND` 默认值由 `bocha` 改为 `auto`；新增 `AutoSearchEngine`：短超时（8s）尝试博查 → 网络类失败（连接失败/超时/5xx/429）进入冷却（默认 60s）并降级 mock → 冷却结束自动重试，网络恢复即自动切回真实搜索
- config 新增 `AUTO_SEARCH_TIMEOUT`（默认 8）/ `AUTO_SEARCH_COOLDOWN`（默认 60）
- 场景实测：有网=bocha 真实结果；断网=mock(auto) 兜底话术；冷却期内 0.00s 直接返回 mock；网络恢复自动切回 bocha；未配置 key 不报错直接 mock；router fallback 联动正常

### 8.2 RAG 联网兜底（方案A，2026-09-12）

- 需求：问题回答（course_qa 分支）也能在知识库检索不可靠时联网，而非仅意图识别 fallback 可触发搜索
- 实现：`qa.py` 重构为手动「检索 → 分数判断 → 生成」流程（不再依赖 langchain_classic retrieval chain）
  - `retriever.retrieve(with_score=True)` 拿 top1 距离（Chroma L2，越小越相关）
  - 检索为空或 top1 > `RAG_FALLBACK_DISTANCE`（默认 0.95；实测库内≈0.66~1.05 / 库外≈0.99~1.51）→ 转 `make_search_engine().search()`
  - 网络可用 → 搜索结果作上下文生成，来源标注「网络搜索」；网络不可用 → 如实提示，不硬凑答案
- config 新增：`RAG_SEARCH_FALLBACK`（默认 true）/ `RAG_FALLBACK_DISTANCE`（默认 0.95）
- 实测：库内强相关走本地（来源=文件章节）；库内弱相关/库外问题走联网（来源=网络搜索，2026 AI 进展、北京天气均真实命中）；开关关闭全走本地；断网如实提示
